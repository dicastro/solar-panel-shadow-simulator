Annual Simulation Guide

1. What the annual simulation does

The annual simulation steps through every time interval of a full calendar year — for example every hour, or every 15 minutes — and for each step it:

  1. Computes the sun's position (altitude and azimuth) from the installation's GPS coordinates.
  2. Casts rays from sample points on every panel toward the sun to detect which zones are shaded by walls, railings, or other panels.
  3. Calculates the power output of each panel, accounting for bypass diodes, string mismatch losses, DC optimizers, and (when weather data is available) real irradiance and temperature.
  4. Accumulates energy (kWh) per panel per hour of the year.

The result is a complete picture of annual production for every setup defined in your configuration. Setups can then be compared side by side in the results panel.

2. Geometric model vs Open-Meteo

The simulator offers two irradiance models that differ in accuracy, data requirements, and available options.

Feature Geometric (clear-sky) Open-Meteo (real weather)
Internet required No Yes (first run per location/year)
Weather accuracy Assumes constant clear sky — overestimates on cloudy days Uses real historical hourly DNI, DHI, and temperature
Available years Current year and past 5 years Past 5 completed years only
Available intervals 15 min, 30 min, 1 h 1 h only
Best for Quick layout comparisons, current-year estimates Realistic annual production estimates

Why can't Open-Meteo cover the current year?

Open-Meteo's historical archive only includes completed past years where the full reanalysis dataset is available. The current year is still in progress, so hours in the future would contribute zero production and distort the annual total. The geometric model does not have this limitation — it can project forward in time using the sun's deterministic position.

Why does the geometric model support shorter intervals?

Open-Meteo provides irradiance values at hourly resolution. Interpolating between hours would introduce errors, so the minimum interval is locked to 1 hour when using Open-Meteo. The geometric clear-sky model has no such constraint — the sun's position can be computed at any point in time, so 15-minute and 30-minute intervals are available.

How Open-Meteo data is used

When Open-Meteo is selected, the simulation fetches hourly Direct Normal Irradiance (DNI), Diffuse Horizontal Irradiance (DHI), and ambient temperature for the full year. The simulator then computes the Plane-of-Array (POA) irradiance — the actual irradiance hitting the tilted panel surface — by combining direct, diffuse sky, and ground-reflected components. A temperature correction is also applied: hot cells lose efficiency, and cold cells gain it slightly.

Open-Meteo data is cached locally after the first download. Re-running the simulation with the same location and year will not make another network request.

3. NxN sample points per zone

Each bypass-diode zone on a panel is sampled by an NxN grid of points. A ray is cast from each point toward the sun. The more points, the more accurately the simulation detects partial shading within a zone.

N=2: 4 sample points per zone

N=4: 16 sample points per zone (default)

N=8: 64 sample points per zone (high precision)

Higher N catches more precise shadow boundaries — a thin chimney shadow crossing a zone at an angle is detected accurately with N=8 but might be missed or exaggerated with N=2. However, the number of rays grows as N², so doubling N quadruples computation time. The default N=4 (16 points per zone) is a good balance for most installations.

4. Zone shadow threshold

The threshold T defines how many sample points must be shaded before the entire zone is considered blocked and its bypass diode activates. This allows you to control sensitivity to partial shading.

T=1: any shaded point blocks the zone (most sensitive)

T=4: 3 shaded points — zone still active

T=4: exactly 4 shaded points — zone blocked

A threshold of 1 means the zone trips as soon as any single point is in shadow — maximum sensitivity to thin shadows. A higher threshold requires more extensive shading before the diode activates, which models real-world bypass diode behavior more conservatively. The default threshold of 1 gives the most pessimistic (safe) production estimate.

The maximum threshold is NxN (all points in the zone). Setting it to the maximum means a zone is only considered blocked when every single sample point is shaded.

5. Parameters and their trade-offs

The simulation panel shows three computed quantities before you run:

Quantity Formula Effect on precision / time
Total sample points Total zones across all panels × N² More points → finer shadow detection → more rays to cast
Time steps 365 days × 24 h × (60 / interval) Shorter interval → smoother production curves → more steps
Total rays Total sample points × time steps Direct measure of computation work

Typical guidance:

  • Quick comparison: N=4, interval=60 min. Runs in seconds to a few minutes.
  • Detailed analysis: N=4 or N=6, interval=30 min. Noticeably longer but still feasible.
  • High precision: N=8, interval=15 min. Can take many minutes; use only when needed.

6. Parallel calculation

When you run the simulation with multiple setups, each setup is calculated independently and simultaneously using the available processor cores. A computer with 8 cores can run up to 7 setups in parallel (one core is always reserved for the browser interface so it stays responsive). If you have more setups than available cores, the remainder are queued and start automatically as others finish.

Progress bars appear in the simulation panel — one per setup currently being calculated — with a real-time percentage and estimated time remaining. The ETA becomes accurate after the first 5% of the calculation has completed.

The simulation runs entirely inside your browser. No data is sent to any server. Closing the browser tab or navigating away will interrupt the calculation.

7. Cache and result management

Every completed simulation run is saved automatically in your browser's local storage. The next time you run with the exact same parameters (year, interval, irradiance model, density, threshold) and the same configuration, the result is loaded instantly from cache — no recalculation needed.

If you change the configuration (panel layout, wall dimensions, GPS coordinates, etc.) after running a simulation, the results panel will show a warning that the stored results are outdated relative to the current configuration. You can keep the old results for reference while re-running the simulation to get fresh ones.

To view and manage cached results — including deleting individual runs or clearing all cached data — open Settings → Cache management in the sidebar.

Clearing the browser's site data or storage from the browser settings will also delete cached simulation results. Use the backup export feature (Settings → Export / Import) to save a copy before doing so.
